# PR Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Review a session's PRs inside deckhand: a full-file diff with grouped, noted files, and line comments that go straight to a review Claude.

**Architecture:** A review is a normal Claude session (its row's `PaneID` is the Claude pane) plus one extra tmux pane that runs `deckhand review <id>`, a Bubble Tea program that draws the file column and the diff. When a review row is shown, the Claude pane is swapped into the slot as today and the review pane is joined above it; before any other pane is shown, the review pane is broken back out to `deck-bg`. Review data lives in `DECKHAND_HOME/reviews/<id>/`: `review.json` (which PRs, which is current) and `pr-<n>.json` (groups and notes, written by the review Claude).

**Tech Stack:** Go 1.27, Bubble Tea v2 (`charm.land/bubbletea/v2`), bubbles `textinput`, lipgloss v2, tmux, git, `gh`.

**Spec:** `docs/superpowers/specs/2026-11-03-pr-review-design.md`

## Global Constraints

- No code comments. No em dash characters anywhere (code, strings, commits, PR body).
- Few tests: one per rule, at the lowest layer. Bent's rule overrides this skill's TDD default: only the tests named in this plan get written.
- Every test command runs as `env -u TMUX -u CLAUDE_CONFIG_DIR CLAUDE_HOME=$(mktemp -d) DECKHAND_HOME=$(mktemp -d) DECKHAND_SOCKET=deckdbg-test TMUX_TMPDIR=$(mktemp -d) go test ./...`. Nothing may write under `~/.claude`; after any harness run, `grep -l deckdbg ~/.claude/sessions/*.json` must print nothing.
- Never touch the tmux sockets `deckhand` or `claude-deck`.
- Reuse the existing styles in `internal/ui` (`gray`, `white`, `yellow`, `red`, `selectionBar`) and the `artifactList` dialog pattern. Do not invent new dialog shells.
- Keys: `v` starts a review. In the review pane: `j` `k` `↑` `↓` line, `n`/`N` change, `]`/`[` file, `J`/`K` PR, `c` comment, `enter` send, `esc` cancel. `ctrl-j`/`ctrl-k`/`ctrl-q` are not rebound.
- Groups, in this order: Changes, Refactor only, Imports only, Tests, Generated. Tests and Generated start folded.
- Branch from `origin/main`: `git fetch -q && git checkout -q -b pr-review origin/main`, then `git cherry-pick` the spec and plan commits from `pr-review-design`.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. The session folder is not a git checkout of the PR's repo (or not a git repo): `v` shows a red hint and starts no session.
2. A comment is sent while the review Claude asks a question or a permission: the comment waits and goes after the question is answered; it never types into the question.
3. A stacked PR whose branch is not checked out: the diff comes from the head ref, the header says "not checked out", and the folder's working tree is not read for it.
4. Binary files, deleted files and renamed files in the PR: each shows one sensible line or its old content, never a crash or an empty pane.
5. The review Claude is suspended, dies or the `ui` process restarts while the review pane exists: the orphan review pane is killed, and showing the review again recreates it.

Items 1 and 3 get unit tests in Task 2. Items 2, 4 and 5 are checked in the harness in Task 6.

- [ ] **Step 3: Implement `git.go`, `prompt.go` and `gh.Info`**

`Resolve`: `git -C cwd rev-parse --show-toplevel` fails, so return `folder is not a checkout of <repo>`. When `git remote get-url origin` exists and does not contain the repo name, return the same error; a repo without `origin` is accepted (the test repo has none). Head ref: `refs/heads/<head>` if it exists, else `origin/<head>`. Base ref: `origin/<base>` if it exists, else `<base>`. `MergeBase` is `git merge-base <base> <head>`. `CheckedOut` is `git branch --show-current == head`. Start `git fetch -q origin <base> <head>` in the background first; ignore its error.

`Changed`: `git diff --numstat -z -M <mb>` when checked out (working tree), else `git diff --numstat -z -M <mb> <head>`. A `-` count means `Binary`. Renames give `OldPath`. For each file, read the first 512 bytes of the new content and call `Fixed`; get the attribute from one `git check-attr -z linguist-generated -- <paths>` call.

`FileDiff`: `git diff --no-color -U1000000 -M <mb> [head] -- <old> <new>` passed through `ParseFull`. A binary file returns one `Same` line with text `binary file`.

`NotesPrompt` text, exactly:

```
Review PR #{n} "{title}" (branch {head}, base {base}). Read the change with: git diff {mergeBase}{ {head} when not checked out}
Write JSON to {notesPath} shaped {"files":[{"path":"...","group":"changes|refactor|imports","note":"..."}]}.
List changes most important first. Use refactor when behaviour does not change and imports when only imports change. Skip test and generated files.
Each note says in one or two short lines what the change does and where it fits.
Then wait for my review comments. Discuss when I ask, change code when I tell you to.
```

`CommentPrompt` text, exactly (the second line is `> ` plus the line text; for a deleted line use `{path} removed line {old}` in place of `{path}:{new}`; add ` not checked out` after the branch when `!CheckedOut`):

```
Review comment on PR #{n}, {path}:{new} (branch {head}):
> {line text}
{comment}
```

- [ ] **Step 1: Implement the model**

Load `review.State` and the current `PR`, call `Resolve`, `Changed`, `LoadNotes`, `Arrange`, then `FileDiff` for the selected file. Every second compute a fingerprint (`git status --porcelain -z`, `git rev-parse HEAD`, mtimes of `review.json` and the notes file); reload on change, keeping the selected path and the cursor's new line number where they still exist. Draw only the visible lines.

Keys as in Global Constraints. `n`/`N` jump to the first line of the next or previous run of Add or Del lines. `]`/`[` skip folded groups. `t` folds or unfolds Tests and Generated together (Claude's call: the spec says "opened", and `enter` belongs to the comment box). `J`/`K` change `State.Current`, save it, and when the new PR's number is not in `State.Asked` and its notes file is missing, send `NotesPrompt` and append the number to `Asked`.

- [ ] **Step 2: Implement the view**

File column on the left, 30 columns (clamped to a third of the width): first line `#<n>` and `J/K PR`; then each non-empty group as a gray header, folded groups as `▸ Tests (4)`; each file as its base path and `+a -r`, the selected file with `selectionBar`. When `!CheckedOut`, the header line says `not checked out` in yellow. Diff on the right: first the note in purple (lipgloss color `147`) wrapped to at most 2 lines, then the lines with the new line number, Add in green, Del in red, the cursor line with a gray background. Last line: `j/k move  n next change  ]/[ file  J/K PR  c comment  t tests`, or the comment box.

- [ ] **Step 3: Implement sending**

Find the Claude pane: the pane whose `@deck-session` is the review id. If none, show `review session is not running` in red and keep the box text. If `live.Running` reports status `waiting` for the id, show `waiting for Claude to finish asking` and retry every second. Otherwise `set-buffer -b deck-review <text>`, `paste-buffer -p -d -b deck-review -t <pane>`, `send-keys -t <pane> Enter`. Clear the box after a send.
